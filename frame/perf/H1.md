## Causes (confirmed headless where possible)

1. **Half speed: the game ran at 38 game frames a second in the race.** aurora called
   SDL_SyncWindow on every game frame. On X11, when the window's geometry differs from what SDL
   expects (gamescope sizes the window itself; Xvfb has no window manager) and nothing is pending, it
   ends in SDL_Delay(10): 10 ms of every game frame on the game thread. Menus (6 ms of game logic) still
   made 60; the race (13 to 17 ms) dropped to 38, and Mario Kart's logic is frame-locked, so the race
   ran at 63 % speed. Mock A/B on one build (1728, sysmem, pipelined, demo race): old behaviour
   (`KARTFRAME_SYNC_WINDOW=1`) 38.1 game fps, 72.9 sets/s, 3.7 % late; fixed 59.8
   game fps, 120.6 sets/s, 0.0 % late, GPU 4.70 / 5.35 ms a set (old 6.13 / 8.17). Commit 57526ee.
2. **Judder and head-turn ghosting: half rate.** The old rule dropped to every second refresh at
   13 late of 240 and came back after 10 s; it flapped 16 down / 15 up, 33 % of all ticks were
   repeats, and 115 of the 143 race seconds ran at half rate (60 Hz content shown twice). Half rate
   is now off by default (late sets repeat the retained layer, which SteamVR reprojects); commit
   b240caf.
3. **Race GPU 5.8 to 6.9 ms a set** (p99 to 11), above the mock's 4.7 / 5.35 with the fix. Part of
   that may be cause 1 (the mock's old-behaviour run also showed 6.1 / 8.2), part SteamVR's own GPU
   work (0.8 ms) and the headset's clocks. Unconfirmed until the next session.
4. **Flicker of the 2D screen.** In 67-100 (race scene on the virtual screen) the immersive
   display-copy source region alternated every game frame between the display copy (893x456) and the
   full-EFB fallback (939x528): 1100 log lines in 33 s. The 2D content is scaled from that region, so
   alternate frames were 5 % wider and 16 % taller. Menus are now a quad layer (commit b240caf); the
   fallback frequency is logged every 10 s now ("Immersive display-copy source: N frames with a
   display copy, M with the full-EFB fallback"). Whether the race HUD alternates the same way on the
   headset is to be read from the next session's log.
5. **Projected menus.** Not the GPU cost (2.1 ms a set, intro included: mock with the welcome and
   controller guide shown, sysmem 2.10 / 2.87, tiled 2.06 / 2.70), but every menu set was rendered for
   both eyes and encoded at 2.9 ms. Menus are now a quad fixed in the room, cropped to the picture
   (1728x972 of the 1728 square), as GalaxyFrame; the first-run guide stays projected.
