# H3 (2026-10-13 13:22, third headset session): what happened, and lane H's fixes

Session `$KARTFRAME_HOME/sessions/20261013-132235` (game.log, vrtiming.log, report.txt), build `native`
ff9b277 (lane G's fixes). Owner: no doubled images; "the frame rate felt really bad, flickering, it
hurt, kind of nauseous"; "half speed at the start, every second of game time took two, better later";
HUD practically fixed. Requests: (R1) full-screen 2D effects (Blooper ink, the black of a respawn)
across the whole view; (R2) remove a thin transparent vertical line right of the map. Later: the menu
laser's part over the screen and its target mark were hidden.

Session: 3.1 min, race 137 s at 90.8 sets/s, 24.2 % late, GPU 6.68 ms/set p50 (H2: 5.9), encode 2.59;
SteamVR: app frames reused 4.4 % (H2 0.2), mispresented 1284 (H2 116).

## Causes

1. **Half speed at the race start: a PrimeFrame build.** Its ninja log: 1172 jobs written 13:23:25 to
   13:23:44 (mostly cache hits); the game started 13:22:46, the race at t=41. Slow game frames
   (`hitch:` lines) per 10 s: 192 and 285 in t=40-60, at 21.5 / 15.7 ms of game CPU and 4.0 / 3.7 ms
   run-queue wait each; afterwards 33 to 164 per 10 s at ~14 ms game CPU and 0.7 ms run-queue. The
   build is paused by the headset-in-use marker now (orchestrator).
2. **Flicker: 20 to 36 % of race sets late, the whole race.** GPU p50 6.3 to 7.3 ms a set, p99 9 to
   10, against ~7.5 ms of GPU per 8.33 ms refresh left beside SteamVR's compositor: a late set repeats
   the retained layer and the scene stalls a refresh. Lane G's end-time rule made it worse: every
   layer was ended with its poses' locate time, so each late set went out with a display time one
   refresh older than its cycle's prediction (SteamVR counts such frames as mispresented; 1284 here).
3. **"Located for another time than their cycle's ~1180 of ~1190" was not an off-by-one.** SteamVR's
   predictions jitter by +-0.02 ms; a pipelined set is located for "this prediction + one period", so
   nearly every set differed from its showing cycle's prediction by microseconds. Only the late sets
   (the -8.3 ms minimum) were a refresh off. The display lead was 25.06 ms in menus and 27.18 in the
   race (3 refreshes; the mock had 2).
4. **GPU per set 6.7 ms vs H2's 5.9 is not lane G's cost.** Same mock race (Grand Prix, HUD on the
   screen, real FOVs, 3-refresh lead): H2's build 4.92 ms, H3's build 5.05, H3's with
   KARTFRAME_SCENE_CLOCK=0 5.03. The headset difference is not reproduced headless; candidates are the
   SoC's state in a third session of the day (CPU 85 to 90 C under load here) and SteamVR. Unconfirmed.
